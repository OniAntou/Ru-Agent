# Verification evidence - 2026-10-31

Historical snapshot only. These results describe the recorded working tree and
conditions, not current acceptance. See [current verification](../../operations/verification.md).

## Tool read ergonomics

A model reads an empty `read` page as a broken tool. `read` and `read_file` now
carry a `notice` that names the actual situation: the file exists but is empty
(0 bytes), the requested `offset`/`start_line` is at or past the end (with the
real byte or line count), or content remains and where the next page starts. A
page cut by the output budget says so and points at `next_offset` instead of
ending on a bare `truncated` flag. `read` also reports `estimated_tokens` for the
returned content, so the model can budget in the unit it is billed in.

`FileReadOutputBudget` now reserves 256 bytes for fields added after fitting, so
notice and estimate cannot push the envelope past the 4 MiB cap. The
`ModelToolHeadroomRegressionTests` case caught that before the reserve existed.
The two changed tool descriptions updated the tool-contract golden lock
deliberately (description SHA-256 rows for `read` and `read_file`).

Broker 1,445 tests passed for this change in isolation (`FileReadAdapterTests`,
`FileLineReadTests`, headroom and tool-contract tests included).

## Tool telemetry counters

The comparison with Claude Code's read tool showed a measured dedup win (18% of
reads were same-file collisions). Ru now measures the same question before
changing behaviour: the Broker source emits `ru.tool.calls`
(`tool.id`, `tool.status`, `error.code`) and `ru.tool.read_pages`
(`tool.id`, `repeated`). `repeated` is answered by a bounded per-service path
tracker that never withholds content; a real "file unchanged" answer needs the
Host's compaction-aware read state, so dedup stays a separate decision.

The Host's meter provider now adds the Broker source, without which the counters
would be produced but never collected. Tags follow the existing allowlist:
bounded tokens only, never paths or arguments. Two listener tests pin the first
read (`repeated=false`), the second (`repeated=true`) and a failed call's status
and bounded error code.

## Model persona names the model, not the product

Asked which model it was, the model answered "Ru Agent". The cause was the first
sentence of the core contract: "You are Ru Agent". The environment block already
carried the serving model id, but it read as metadata next to a first-person
identity claim.

The persona block now opens with that id - "You are <model>, a coding model
running inside Ru Agent" - states that Ru Agent is the host product and not the
speaker's name, and requires model or version questions to be answered with the
id from the environment block. The product name in the GUI and terminal is
unchanged; only the model-visible identity moved. A test pins the identity
sentence and that "You are Ru Agent" no longer appears in the contract.

## Flaky and hung runs observed

The first full matrix failed one CLI test,
`TgSquareWordmarkRasterTests.Frames_use_two_buffers_and_do_not_redraw_or_allocate_during_quiet_time`,
an allocation-sensitive wordmark check unrelated to these changes. It passed
alone (13/13 in the class) and in the final matrix, so the first failure is
recorded as environment-sensitive rather than a regression.

A second matrix then hung in `RuAgent.Cli.Tests` with no output for ~18 minutes.
Stale `dotnet`/`testhost` processes from the aborted first matrix were still
alive; after they were stopped, the CLI project passed alone (2.058 tests,
3m28s) and the full matrix passed cleanly. The hang is recorded as process-state
contamination from the aborted run, not a defect in the suite.

## Not measured
