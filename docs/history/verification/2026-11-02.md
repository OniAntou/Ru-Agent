## New-session transition work

The user reported visible stuttering in both the sidebar and conversation/composer
when creating a session. Deterministic regressions reproduced two sidebar problems:
replacing an empty draft published two renders with an intermediate empty list,
and creating a recent chat collapsed/replaced an unrelated workspace header.

Draft replacement now publishes one render. Existing workspace expansion is kept
as the default for subsequent projections, and unchanged headers retain their
container identity. Selecting a session still opens its previously collapsed group.
Sidebar rows use repositioning without competing add/delete theme transitions;
the existing Windows animation-preference callback reconfigures these transitions.

The known-new session path paints an empty transcript after the existing detach,
draft-retention and preset-narrowing steps. It skips activation/history, replay,
usage and run-adoption reads for a session whose create response already establishes
an empty history. Side-panel layout is deferred before reset and committed with
the new transcript. A new no-project chat does not display the outgoing workspace
path. Creating a session while already on chat also avoids restarting navigation's
model/catalog refresh work. Existing-history replay and cancellation ownership remain.
