# Implement a transactional dependency scheduler

Implement a deterministic in-memory scheduler for jobs with dependencies and bounded retries. The API lives in `src/scheduler.py`; data records live in `src/models.py`. `Job(id: str, depends_on: tuple[str, ...] = (), max_attempts: int = 1)` describes a job. `Scheduler(max_parallel: int)` owns one graph and its runtime state.

`replace(jobs)` validates the entire proposed graph before changing anything: IDs are unique non-empty strings, dependencies are unique and refer to another proposed job, self-dependencies are invalid, `max_attempts` is a positive integer (bool is invalid), and the graph is acyclic. Invalid input raises `ValueError` and leaves the previous graph, states, attempts, and transition history unchanged. A successful replacement resets all jobs to `pending`, attempts to zero, and history to empty. Job input order does not affect dispatch order.

`ready() -> tuple[str, ...]` returns lexicographically sorted pending jobs whose dependencies are all `succeeded`, capped by currently available parallel slots. `start(job_id) -> int` starts one currently ready job and returns its one-based attempt number; otherwise raise `ValueError`. `succeed(job_id)` and `fail(job_id)` require a running job and return its new state string. `fail(job_id)` changes the job to `failed`. `retry(job_id)` moves a failed job back to pending only when another attempt is available; it returns false when retry is not allowed and does not change history. Each `start` consumes the shared `max_attempts` budget, so retrying does not reset attempts.

`cancel(job_id)` changes a pending or running job to `cancelled`; cancelling a terminal job raises `ValueError`. When a dependency becomes `failed` or `cancelled`, recursively mark pending descendants `blocked`; a running descendant is never silently rewritten and remains running until it completes. Blocked jobs never become ready. `state(job_id)` returns the state and raises `ValueError` for an unknown ID. Invalid state transitions raise `ValueError`; an unknown or non-retryable ID passed to `retry` returns false. Expose `history` as a tuple of `(job_id, from_state, to_state, attempt)` records. Record every actual state change exactly once; do not record no-op retry refusals. Use the states `pending`, `running`, `succeeded`, `failed`, `cancelled`, and `blocked`.

Concurrent worker completion order must not affect ready ordering. The smoke script covers a simple two-step DAG. Hidden groups exercise failed atomic graph replacement, generated DAGs, capacity, transitions, retry exhaustion, cancellation, blocked propagation and invalid state operations. The bilingual display label `dịch vụ dữ liệu` is ordinary job metadata in the examples; IDs and ordering are byte-for-byte Python strings. Edit only `src/**/*.py`.
