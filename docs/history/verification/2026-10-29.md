## Repairs following the completed benchmark

The scoped working-tree implementation adds explicit `supersedes` metadata to
terminal verification calls. It satisfies only a retired previously passing
stale check after an appropriate replacement passes fresh in the same canonical
cwd. It cannot retire failed, pending, negative or unknown-freshness checks.
Original evidence is retained, and later changes reopen the obligation. Core
regressions and a SQLite warm-cache/cold-replay/compaction test cover this lifecycle.

Python repair-family evidence also recognizes complete empty pytest discovery
(exit 5 plus the no-tests diagnostic), allowing a meaningful passing correction
in the same resolved Python interpreter/cwd. Direct inline parse errors remain
repairable; actual test failures, collection errors, truncated output and
negative-test mismatches do not gain this exception. File-tool guidance now
explicitly distinguishes creation, partial editing and deliberate replacement;
long Python code is directed to file/argv execution rather than malformed strings.

## Grader corrections: coalescer and pager loader timing

The `ts-abortable-coalescer` groups `shared_inflight` and `clear_generation`, and
the `ts-generation-pager` group `same-generation-dedup`, asserted `calls === 0`
right after `run()` or `loadNext()`. That required the loader not to run
synchronously. The task text only requires concurrent calls to share one loader
call and does not say when the loader runs, so a synchronous implementation failed
on a requirement the task does not state. The pager assertion also bundled this
timing claim with `one === two`, which the task does require.

The pre-settlement `calls === 0` assertions were removed. The spec claims stay:
`one === two` in the pager group and the one-loader count checks. The two dedup
groups now also assert exactly one loader call after the shared request settles
(`shared_inflight`, and `same-generation-dedup` after `Promise.all`).
`clear_generation` checks generation separation rather than sharing, so it gained
no dedup assertion. Group names, group counts and other expectations are unchanged.

The retained one-microtask checks (`calls === 1` after `await Promise.resolve()`)
still assume the loader starts within one microtask. An implementation that defers
the loader by two or more ticks would fail them. The task does not require that
timing, so this is a known limit of those groups.

Oracle results. The starter and reference were graded by the repository self-test.
The variants differ from the reference only in loader timing or dedup, and were
graded in a scratch directory outside the checkout.

| Task | Starter | Reference | Synchronous loader | Extra loader call for a shared request |
| --- | --- | --- | --- | --- |
| `ts-abortable-coalescer` | Fails all 5 fail-to-pass groups; passes the 3 pass-to-pass groups | Passes 8/8 | Passes 8/8 | Fails `shared_inflight` (and `abort_isolated`) |
| `ts-generation-pager` | Fails 4 groups | Passes 6/6 | Passes 6/6 | Fails `same-generation-dedup` on its loader-count checks |

Under the previous grader, the synchronous variant failed `shared_inflight` and
`clear_generation` for the coalescer and `same-generation-dedup` for the pager,
while the reference still passed. This is the over-strict behavior removed here.
