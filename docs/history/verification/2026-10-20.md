## Hard-task live run, 2026-10-20 (default settings)

Nine hard Terminal/SWE tasks x 2 attempts on `minimax/minimax-m3.1-flash:free` with the saved settings: **10/18**.
Both attempts passed: `cs-single-flight-cache`, `py-migration-rollback`, `py-stream-parser`. One of two: `cs-atomic-ledger`, `cs-lease-renewal`, `py-dependency-scheduler`, `ts-transaction-store`.
Both failed: `ts-generation-pager` (grader requires unstated behavior) and `ts-session-replay` (malformed events are rejected without mutation).
One `runtime_drive_failed` (`ArgumentException` right after a `tool.proposed`) was seen twice across all runs and did not reproduce in three further `cs-lease-renewal` attempts (0/3 drive failures, 1/3 passes). Cause still unknown; set `RU_DRIVE_FAILURE_DIAGNOSTIC` to a file path to capture the exception if it recurs.
Single small sample on a free model; treat as variance-limited.

Follow-up with the `exception_site` Host, four of the variable tasks x 3 attempts: **6/12** (`cs-atomic-ledger` 2/3, `cs-lease-renewal` 2/3, `py-dependency-scheduler` 1/3, `ts-transaction-store` 1/3). No `runtime_drive_failed` in these 12 runs, so it has now been seen 2 times in about 35 live runs. The recurring failing groups are snapshot isolation (two tasks) and `transition-integrity`; checked against the reports: `transition-integrity` fails because `replace(None)` raises `TypeError` where the task text says invalid input raises `ValueError`; `ts-transaction-store` fails because the returned snapshot and its values are not frozen although the task asks for an immutable snapshot. These are model misses against stated requirements, not harness faults.

Prompt-guidance check (2026-10-20): nine hard tasks x 1 on the same model after the tool "when to use" guidance, the delegation line and the user-wide instruction file: **4/9** against a baseline of 10/18, no `runtime_drive_failed` or other system error, mean output tokens about 747 against about 640 to 690. The differences are within the run-to-run variation recorded above, so the change is accepted as a regression guard pass, not as evidence of improvement.
