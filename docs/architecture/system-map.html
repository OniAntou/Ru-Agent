Ru architecture at a glance

Ru là một coding agent chạy native trên Windows: desktop WinUI 3 và terminal/TUI cùng nói chuyện với một Public Host loopback bằng HTTP/SSE. Host sở hữu orchestration, model generation và durable state; nó compose Broker library ngay trong process, và Broker là authority duy nhất cho mọi side effect. Bản đồ dưới đây được đọc lại từ codebase tại HEAD 14a2072f.

01Process và trust topology

Mọi thứ nằm trong process Host (nền xám) đều là code .NET 10 compose trong cùng một process; chỉ client và model provider là ranh giới ngoài. Host bind ephemeral loopback port và ghi URL thật vào runtime descriptor sau readiness. Broker giữ policy, approval và toàn bộ file/terminal/network/computer adapter; Harness không tự chạy tool, nó chỉ đi qua IToolGateway.

02Một agent run, từ đầu đến cuối

Time chảy từ trên xuống. Host tạo run và pin provider trước; Harness giữ state machine, gọi Model Step để chuẩn bị request, rồi lặp model ↔ tool: model trả tool call, Harness gửi qua gateway, Broker chạy side effect và trả result. Mọi bước được ghi durable event; client nhận lại qua SSE frame. Broker không bao giờ được gọi trực tiếp bởi model — chỉ qua `IToolGateway`.

06Ba invariant đáng nhớ

Một authority. Mọi side effect đi qua Broker; model chỉ đề xuất tool call, Harness gửi qua gateway, Broker kiểm tra canonical path/target, policy của session, approval token dùng một lần rồi mới chạy.

Pin cho run. Provider, model, protocol và tool identity không được thay giữa chừng; lỗi trả code có tên, retry chỉ trong cùng selection, không fallback sang provider khác.

Host orchestration, không phải execution. Host giữ auth, conversation/lịch sử, run creation, model step; Harness Core giữ state machine; Broker giữ side effect. Ba tầng này không được trộn authority vào nhau.
