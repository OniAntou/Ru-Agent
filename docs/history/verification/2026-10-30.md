## Requirement checklist and completion review

The prompt now asks the agent to record each explicit requirement of a coding
request as its own `todo_write` item, and to close that item only after a check
exercises it. Before the final reply, the agent re-reads the request and the
changes it made. Completion evidence is durable: a sticky source-edit flag and
the latest successful `todo_write` list.

Two one-time holds can apply to a non-empty final reply, after the existing
`unverified_source_edit` hold. `open_todos` holds when the latest list still has
open items. `completion_review` holds when source was edited and verified, no
`unverified_source_edit` note was raised, and no list is fully completed. Neither
hold is a failure path.

## GUI image attachment intake

Reproduced the picker/drop/clipboard image path using the same
`MemoryStream.AsRandomAccessStream()` adapter as `ChatView`: the signature probe
called `GetInputStreamAt`, which throws `NotSupportedException` because that
adapter cannot clone streams. Text files bypass this probe. The view logged the
exception without composer feedback, so attaching an image appeared to do nothing.
The existing small-image test used a native `InMemoryRandomAccessStream` and did
not exercise the failing adapter.

so the decoder retains its input. Intake exceptions now show composer feedback
